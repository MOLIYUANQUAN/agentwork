# agentwork

人和每个人的 agent 一起干活。每个人的 agent 都是全队的员工：你的 Claude Code 能给队友干活，队友的也能给你干。人在群里说一句，agent 去干，干完交一张结果卡，人看了点头。

## 现在能跑的版本（`mvp` 分支）

一个像微信桌面版的网页群聊，人和每个人的 agent 都是群成员：每个群自带「助手」；一条命令把你电脑上的 Claude Code 接进来；队友也能 @ 它，但只能让它看和回答。

```
Windows：双击 start.cmd
Mac / Linux：./start.sh
然后打开 http://localhost:8787 ，测试账号在 test-accounts.txt
```

做了什么、怎么验收、还没做的：[docs/验收.md](docs/验收.md)。当初的计划：[docs/mvp.md](docs/mvp.md)。

下面是这个方向最初的想法（比现在的版本大，结果卡、审阅这些还没做，也暂时不打算做）。

## 为什么是这个方向

1. **需求是真的。** 人们已经在用很笨的办法做这件事：室友直接登你的账号用你的 Claude Code；大家把各自 agent 的结果复制粘贴到微信群里。有人在用笨办法解决的问题，就是真问题。目前只有身边的例子，还不够，但方向对。
2. **时机对。** agent 已经能完整地干活了，可人们干活的地方，微信、飞书、钉钉，还是为「人找人」设计的，AI 只是后来塞进去的助手。这和 2023 年很像：模型已经会写代码，编辑器还是老的，Cursor 就是在这个缝里出来的。
3. **我们赢的方式。** 不在旧软件上加 AI，而是做一个从头就为 agent 干活设计的地方。
   - **先让一个人离不开**：把自己的 Claude Code、Codex 和内置 agent 放在一起，几个 agent 并行干、互相查，人只看结果、点头。
   - **再让伙伴自然加入**：彼此的 agent 可以互相借，一份订阅大家受益。团队不是门槛，是下一步。
4. **最难的地方。** 写代码有标准答案，团队的活没有。「人看结果、点头」这一步要做得又快又放心，这是真正要下功夫的地方，也是别人最难抄的地方。
5. **还缺的证据。** 到现在没有任何一家证明过用户会一直用下去，热度是真的，留存还没人证明。所以第一步不是写很多代码，而是用最便宜的办法看看我们自己会不会一直用。

一句话：**需求有人在用笨办法解决，时机和当年的 Cursor 一样，赢法是先让一个人离不开、再让团队自然长出来。还差的，是证明人们会一直用它。**

## 和 Cursor 像在哪、不像在哪

**像：**
- **时机**：能力已经有了，干活的地方还没围绕它重做。
- **打法**：站在开源的基础上做成 AI 原生的版本；大公司只会在旧产品上加一个功能（当年是 GitHub Copilot 插件，现在是飞书 aily），小团队做得更深、迭代更快。
- **用户**：从自己就是重度用户的人开始，自下而上传开。

**不像，以及怎么办：**
- **Cursor 一个人就能用，我们的团队价值要两个人。** 所以第一版先做一个人也离不开的部分，团队是扩张，不是门槛。
- **Cursor 握着模型这一层，我们用的是各家的 agent。** 但 Cursor 一开始也没有自己的模型：它先用 GPT-4，后来也接了 Claude；它握在手里的是喂给模型什么、改动怎么落地、用户接受还是拒绝。后来它用这些数据训练了自己的小模型，专做快速补全、快速应用改动，复杂的推理仍交给最强的大模型。我们一开始也不需要模型，要握住三样：团队的上下文（记忆、历史、文档）、活的结构（活卡、结果卡）、审阅的数据（哪些被接受、哪些被打回）。
- **代码好验收，团队的活难验收。** 这正是第 4 条：结果卡和审阅要下最大功夫。
