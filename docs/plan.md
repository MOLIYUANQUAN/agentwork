# agentwork：人和每个人的 agent 一起干活（方案第五稿）

2026-11-20 · Zeep。参与：尹昊（感兴趣），陈宇涵（待问）。「agentwork」是临时名字，随时可改。

## 一句话

**每个人的 agent 都是全队的员工。** 你的 Claude Code 能给队友干活，队友的也能给你干。人在群里说一句，谁的 agent 去干都行，干完交一张结果卡，人看了点头。

## 最大的卖点：一份订阅，全队都用得上

你有一个 Claude Code 最高档的订阅，自己用不完。在一个公司里，没道理不让伙伴用。现在要么共享账号密码，又乱又容易冲突；要么每人各买一份，又浪费。

我们的做法：**账号不交出去，agent 借出去。** 你的 Claude Code 照旧在你的电脑上、用你的账号跑，队友在群里 @ 它，它就替队友干活。谁用了多少，你看得一清二楚。

- **各带各的**：默认就是每人接自己的 agent。没有 agent 的人用内置的那个。
- **借用**：你给自己的 agent 设一个开关：
  - 只给我用；
  - 队友直接用（同一个团队里默认这个）；
  - 每次先问我。
- **主人优先**：你自己在用的时候，队友的活排队；可以设同时最多几件、每天最多多少。
- **记账**：每件活记下是谁叫的、跑了多久、花了多少 token。月底谁用了谁的多少，一目了然，团队内部要分摊也有依据。
- **电脑关着也能借**：转到你账户里的云端 Claude Code 会话接着干。Friday 已经接通了这条路。
- **只碰该碰的**：队友叫你的 agent 干活，它只在这个群专用的工作文件夹里动，碰不到你电脑上别的文件。这是保护你自己，不是限制借用。

## 核心体验：agent 干活，人看结果

1. **派活**：在群里 @ 任何一个 agent，你自己的、队友的、内置的都行。打字时提示「这件事 Codex 擅长」。没有管事的 agent 在中间转手。
2. **活卡**：随口一句「这周把举报清了」，AI 把它变成一张卡：什么事、谁做、哪天要。状态和到期提醒按规则算，不靠模型。
3. **结果卡**，人主要在这里花时间：
   - 交了什么，直接能看；
   - 依据什么，点开能看原文；
   - 改了哪里，像 Cursor 一样显示改动；
   - 谁查过：点「请 X 查一遍」，换另一个 agent 核对；
   - 三个按钮：接受 / 改一下 / 打回。
4. **不用配置**：邀请链接进团队，一条命令接入自己的 agent，五分钟用起来。

衡量标准：一个团队一周能交付多少件被「接受」的东西，不看消息多不多。

## 架构

```
 浏览器（React + TypeScript）
   │ WebSocket：消息、活卡、结果卡、进度实时推送
 ┌─▼───────────────────────────────────────────────┐
 │ server（Python + FastAPI + Postgres）              │
 │  团队 / 小组 / 成员 / 群 / 消息 / 活卡 / 结果卡       │
 │  调度：这件活交给谁的 agent，排队、主人优先、上限      │
 │  账本：谁叫了谁的 agent、跑了多久、多少 token          │
 │  内置 agent（拷 Friday 的模型循环、工具、确认卡）      │
 │  AI 两处：一句话 → 活卡；结果 → 核对                  │
 └─▲─────────────────────────▲──────────────────────┘
   │ WebSocket（主动连出来）    │ 主人的云端 Claude Code 会话
 ┌─┴─────────────────────┐   └ 主人电脑关着时接手
 │ connector（主人电脑上）   │
 │ 一条命令装好、浏览器里点确认就配对              │
 │ 收到活 → 在这个群的工作文件夹里用无头模式跑 Claude Code │
 │ → 进度、结果、用量发回来；执行借用开关和上限           │
 └───────────────────────┘
        外部：飞书开放平台（读文档）
```

仓库结构：

```
agentwork/
  server/      Python 后端（FastAPI、Postgres、内置 agent）
  web/         React 前端（电脑网页）
  connector/   主人电脑上的连接程序（先用 Node 单文件，一条 npx 命令）
  docs/        方案、决策记录
```

技术栈：Python + FastAPI；Postgres（托管）；React + TypeScript + Vite；连接程序用 Node；部署在 Fly；模型方面，内置 agent 用 Opus 5.5，生成活卡用 Haiku 5.5，核对用 Sonnet 5.5。

## 怎么算成了（第 3 周起看两周）

- 每人每周交出至少 3 件真活，七成以上不大改就接受；
- 一半以上的活跑在别人的 agent 上，也就是借用真的在发生；
- 借出 agent 的人不觉得自己的额度被抢；
- 没人催，大家自己打开它。

## 已知风险

- **厂商条款**：一个订阅给几个人用，厂商可能不认可（Anthropic 的用户条款限制共享账户）。我们的做法是账号不离开主人，由主人的 agent 干活、全程留记录。Zeep 已决定按这个方向做。
- **安全**：别人能叫动你电脑上的 agent。用专用工作文件夹和三档开关挡住。
- **额度被吃光**：主人优先和每日上限。
