# MVP 计划：像 Pachat 一样的网页群聊，人和 agent 都在里面

2026-11-20 晚 · 分支 `mvp` · 目标：Zeep 明早验收

## 做成什么样

打开一个网页（本地 `http://localhost:8787`），长得像 Pachat 和微信：

- **注册、登录**：名字、邮箱、密码。本地用，不发验证码。
- **最左边一列**：我的头像、我接入的 agent（绿点表示在线）、「＋ 接入 agent」。
- **第二列**：「聊天 / 通讯录」两个标签，群列表（带最后一条消息），「＋ 建群」。
- **右边主区域**：群聊。群头写「N 个 agent · M 人」和「邀请」按钮；消息分人和 agent，agent 的消息带「Zeep 的 agent」这样的标签；输入框写着「以你自己的身份说点什么」，打 `@` 弹出群里的人和 agent。
- **agent 回话是实时的**：几秒内出现「正在想…」，接着字一段段冒出来，干完显示「在 Zeep 的电脑上完成 · 用时 40 秒」。

## 有哪些 agent

1. **内置助手**：每个群自动有一个，直接调 Claude API。没有自己 agent 的人也能用。
2. **你自己的 Claude Code**：点「接入 agent」，复制一条命令到终端运行，网页上马上显示「已连接」。之后在群里 @ 它，它就在你电脑上跑 Claude Code，把回答发回群里。
3. **借用**：你把自己的 Claude Code 拉进群，队友 @ 它也能用。默认队友只能让它「看和回答」（读文件、查资料），不能改文件、不能跑命令；你自己 @ 它时可以改它工作文件夹里的文件。每个 agent 有一个开关：「群里谁都能 @」或「只有我能 @」。

> 做出来之后有几处和上面不完全一样，见文末「实际做出来的样子」。

**agent 看得懂群里在聊什么**：每次被 @，都会把这个群最近的聊天一起交给它，不用你重新交代背景。这是我们比「单独找 Claude Code」强的地方。

## 和 Pachat 的不同（这一版就有的）

| | Pachat | 这一版 |
|---|---|---|
| 回复速度 | 分钟级 | 秒级，边想边出字 |
| 接入 | 复制一段话，再手动发配对码 | 一条命令，命令里自带一次性码 |
| 别人 @ 你的 agent | 规矩写在提示词里 | 写死在连接程序里：队友只能看和回答 |
| 群里的上下文 | — | 每次都带上最近的聊天 |

## 不做的

手机 App、推送通知、发文件、飞书、活卡、结果卡、账本页面、电脑关着转云端。这些都等明天你看过再说。

## 怎么搭

```
浏览器（React + TypeScript）
   │  WebSocket：新消息、agent 的字一段段推过来、谁在线
server（Python + FastAPI + SQLite），一个进程
   │  账号、群、成员、消息、agent、一次性接入码
   │  内置助手：Claude API，流式输出
   │  WebSocket：把活派给连接程序，收它的进度和结果
connector（Node 单文件，零依赖）跑在主人电脑上
      收到活 → 在这个群专用的文件夹里用无头模式跑 claude
      → 一段段发回去；队友的请求只给只读工具
```

- **为什么不直接用 Octo**：Octo 是完整的企业聊天软件，要 10 个服务；它的 agent 运行时有 9 万多行，要 Node 24。一个晚上改它，不如自己写一个轻的。从 Octo 借的是做法：agent 用长连接收活；调 Claude Code 时用 `--permission-mode` 控制权限、用 `--resume` 接着上一次的会话。以后要手机 App 和完整的聊天功能，再接回 Octo。
- **调 Claude Code 的方式**：`claude -p --output-format stream-json --verbose`，提示词从标准输入喂进去（不拼进命令行，防注入）；每个「agent × 群」记住一个会话，下次接着聊。队友请求时禁用 `Bash`、`Write`、`Edit` 这些工具。
- **仓库结构**：`server/`（Python），`web/`（React），`connector/`（Node），`start.cmd`（一键启动）。
- **密钥**：内置助手用的 API key 放在本机 `.env`，不进 git。

## 今晚的顺序

1. server：账号、群、消息、WebSocket、接入码。用两个账号互发消息。
2. web：登录页、三栏布局、群聊、@ 提示、建群、邀请链接。
3. 内置助手：@ 它，流式回答，带群里的上下文。
4. connector：一条命令接入，你的 Claude Code 在群里回话；队友 @ 它时只读。
5. 两个浏览器、两个账号，从头到尾走一遍；截图对照，改布局和细节。每轮改完再走一遍。
6. 写「明早怎么验收」，推到 GitHub 的 `mvp` 分支。

## 明早怎么验收

1. 双击 `start.cmd`，浏览器打开 `http://localhost:8787`。
2. 用我建好的测试账号登录（密码在本地文件里），或自己注册一个。
3. 进「测试群」，@ 内置助手问一句。
4. 点「接入 agent」，把那条命令贴到终端运行，看到「已连接」；在群里 @ 你的 Claude Code。
5. 另开一个浏览器窗口登录第二个账号，@ 你的 Claude Code，看它只能回答、不能改文件。

## 实际做出来的样子（2026-11-20 夜里更新）

按上面的计划做完了，细节见 [验收.md](验收.md)。和计划不一样的地方：

- **借用收得更紧**：队友借用时，agent 只能读它「工作文件夹」里的文件，读不到主人电脑上别的地方；不能改、不能跑命令。
- **主人 @ 时**：能读、能改工作文件夹里的文件；默认不能跑命令（连接程序加 `--allow-commands` 才放开）。
- **主人和借用的人各用一个 Claude Code 会话**（每个「agent × 群 × 身份」一个），队友说的话不会进到能改文件的那个会话里。
- **内置助手有三种跑法**，自动选：`.env` 里有 `ANTHROPIC_API_KEY` 就调 API；没有就用这台电脑上登录好的 Claude Code（不给它任何工具）；都没有就进**模拟模式**（假回答，只为走通流程），网页顶上会写明。
- **连接程序跟着服务走**：服务在模拟模式，它也模拟；服务是真的，它就真的调 Claude Code。
- **工作文件夹**：每个群一个，在主人的用户文件夹下 `agentwork-files/<群号>-<群名>`；连接程序加 `--dir` 可以指定一个固定的文件夹。
- **启动**：`start.cmd` 只负责建虚拟环境、装依赖，剩下的（构建网页、建测试账号、选模式、开浏览器、起服务）在 `server/launch.py` 里，Windows 和 Mac 共用一份。
- **测试**：`tests/e2e_api.py`（接口 + 连接程序）和 `tests/e2e_browser.mjs`（真浏览器点一遍）。
